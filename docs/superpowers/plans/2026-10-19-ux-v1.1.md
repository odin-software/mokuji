# UX Implementation Plan

> **Estado (2026-10-19): pospuesto.** El bloque de UI va en una versión
> posterior a la del import de MAL, y antes de ejecutarlo hay que revisarlo
> con una pasada de accesibilidad. La numeración de versión de este plan
> (v1.1.0) queda por definir.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar las decisiones D1–D8 de la auditoría de UX en un solo release (v1.1.0).

**Architecture:** Server-rendered (ADR 0002): cada acción nueva es un POST chico que redirige al detalle. El progreso pasa a ser solo el cursor (`last_read_chapter_number`); el detalle del manga concentra la gestión; la lista y el home se simplifican. Sin JS nuevo salvo marcar el link activo del nav en `web/static/app.js`.

**Tech Stack:** Go stdlib `net/http` + `html/template`, SQLite (modernc), migraciones SQL numeradas en `migrations/`.

**Spec:** `docs/ux-auditoria.md` (sección "Decisiones cerradas" D1–D8 y "Feedback de usuarios" F1–F2).

## Global Constraints

- Branch: `feat/ux-auditoria`. Un solo tag al final: `v1.1.0`.
- Commits de una línea en español, prefijo por área (`library:`, `profile:`, `home:`, `anilist:`, `web:`, `docs:`), con el trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Copy user-facing en español dominicano, tuteo, sin voseo; "aquí" (no "acá"), "email" (no "mail").
- Todo funciona sin JS (forms POST + redirect 303). JS solo como mejora.
- Nada contra prod (`mimir`, `mokuji.org`) sin autorización explícita. No hacer push.
- `go test ./...` y `go vet ./...` verdes al cerrar cada task.

## Review Focus

1. **Capítulos no numéricos** ("Special", "Extra") con cursor NULL: el CTA "sigue con el cap." debe ignorarlos y elegir el menor capítulo numérico. → test en Task 6.
2. **Agregar un manga que ya está en tu biblioteca** (doble click, dos pestañas): debe redirigir al detalle existente, no dar 500. → test en Task 4.
3. **Formato del cursor** 12 / 12.5 / 0: debe mostrarse `12`, `12.5` y nada; nunca `12.000000`. → test en Task 2.
4. **Settings con un solo campo**: el form de digest no debe tocar la visibilidad y viceversa; un POST vacío no cambia nada. → test en Task 9.
5. **`include_read` desmarcado estando al día**: debe ocultar los leídos (llega `0`), no volver al default. → test en Task 1.
